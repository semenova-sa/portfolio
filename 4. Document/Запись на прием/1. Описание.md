# Кейс:Приложение «Запись на приём» для медицинской клиники
## Краткое описание системы:
Мобильное приложение для клиентов клиники «Весёлый дохтур» (Android), позволяющее записаться на платный приём к специалисту: выбрать услугу, врача, дату и время, оплатить онлайн, получить уведомления и управлять записью в личном кабинете. 

Цель — автоматизировать процесс записи и снизить нагрузку на ресепшн клиники.

## Что сделала:
### 1. Формализация требований

- Составила полную матрицу требований: бизнес-требования (БТ), пользовательские (ПТ), функциональные (ФТ), нефункциональные (НФТ), бизнес-правила, системные требования, атрибуты качества, требования к внешним интеграциям.

- Связала каждое требование с этапом CJM (например, «простая регистрация» → ПТ001, ФТ001).

### 2. Customer Journey Map (CJM)

- Разработала CJM для целевой аудитории (женщина, 30–40 лет, средний достаток).
- Описала 11 этапов пути клиента: от формирования потребности до оплаты приёма.
- Для каждого этапа указала: задачу клиента, канал взаимодействия, процессы, чувства и мысли, барьеры, что предлагает клиника, важность этапа (1–5), удовлетворённость (1–5) и решения по улучшению.
- Выявила «провальные» этапы (где удовлетворённость низкая, а важность высокая) и предложила конкретные решения.

### 3. Техническое задание (ГОСТ 19)

- Подготовила ТЗ по ГОСТ 19.201-78 (с листом утверждения, аннотацией, разделами).

- Описала: наименование программы, основание для разработки, назначение, требования к функциональным характеристикам (7 функций), входные и выходные данные, временные характеристики, надёжность, условия эксплуатации, требования к техническим средствам, информационную и программную совместимость, бизнес-правила и ограничения, состав программной документации, стадии и этапы разработки, порядок контроля и приёмки.

### 4. План-график работ (диаграмма Ганта)

- Составила план-график разработки с этапами: анализ требований, проектирование UX, UI-дизайн, разработка backend, разработка frontend, интеграция с внешними сервисами, тестирование, приёмка, публикация и поддержка.

- Указала сроки, длительность каждого этапа, ответственных исполнителей.

- Визуализировала план в виде диаграммы Ганта.

### 5. Интеграции

- Описала интеграции с AMOCRM клиники, платёжными сервисами, push/SMS/email-системами.

## Инструменты:
- CJM: Miro / Google Sheets / Excel

- ТЗ: Google Docs / Word 

- План-график: Excel

- Диаграммы: draw.io
